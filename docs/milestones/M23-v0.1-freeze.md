# Goal

Freeze the accepted real-only source tree as the upstream `0.1.0` release
candidate used by the later Debian/PPA packaging milestones.

# Scope

M23 changes only release metadata, documentation, QA, and packaging handoff
records. It verifies the existing M00--M22 implementation without adding a
numerical API.

# Non-goals

No new BLAS/LAPACK operation, factorization, solver, complex support, sparse
support, public release tag, Debian package, or PPA upload is part of M23.

# Design constraints

`DESCRIPTION` is the single version source and is frozen at `0.1.0`. The
release candidate is identified by one full Git SHA. Archives are generated
from clean trees with the package builder and must be byte-for-byte
reproducible. The MPLAPACK dependency is identified by its required feature
probe and validated source revision, not by a version string alone.

# Implementation tasks

- Freeze user-facing version, NEWS, README, API, compatibility, and limitation
  text.
- Build and compare two independent candidate archives.
- Record the source SHA, archive checksum, dependency provenance, and PPA
  handoff in `docs/v0.1-release-manifest.md`.
- Run fresh-clone, extracted-archive, lifecycle, sanitizer, and full local CI
  checks.

# Required tests

- `tools/local-ci.sh` and the complete M00--M22 regression suite.
- Dependency feature probe and runtime linkage audit.
- Two clean archive builds with identical SHA256 and file lists.
- Extracted archive install/help/example/smoke/uninstall/reinstall lifecycle.
- Compatibility firewall and secret/absolute-path leakage audits.
- `git diff --check` and a clean working tree apart from pre-existing unrelated
  legacy deletions.

# Gate

M23 passes only as `M23 PASS — V0.1.0-RC-FROZEN` when the source-freeze,
version, reproducibility, archive, QA, package, linkage, documentation, and
PPA-handoff gates all pass. M23 does not create the final Git tag or upload a
PPA.

# Expected commit

`M23: record v0.1.0 release-candidate evidence`
