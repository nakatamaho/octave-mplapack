# octave-mplapack v0.1.0 real API

This is the authoritative inventory for the frozen `0.1.0` release candidate.
The tested baseline is GNU Octave 11.1.0 and the numerical backend is the
installed MPLAPACK MPFR library. The public class is `mp`; v0.1 is dense and
real only.

## Construction and precision

`mp(x)` accepts real scalars and dense two-dimensional real matrices. Decimal
text is parsed directly by MPFR (`mp("0.1")`), while a real double is converted
from its already-rounded binary64 value (`mp(0.1)`). Cell arrays of decimal
strings are supported for matrix construction. A fresh process starts at 512
bits. `mpbits()` gets the project default, `mpbits(p)` sets it for future
construction, and `mpdigits()`/`mpdigits(n)` provide the decimal-digit view.
Existing values never change precision when the default changes.

For supported arithmetic, two `mp` operands use `max(precision(lhs),
precision(rhs))`; a mixed real double uses the `mp` operand precision. Every
MPLAPACK invocation uses one uniform operation precision derived from its
operands. No public operation consults `mpbits()` to widen an existing value.

## Supported operations

| Area | Syntax | Result and backend |
|---|---|---|
| Inspection | `size`, `rows`, `columns`, `numel`, `ndims`, `isempty`, `end` | Builtin structural values |
| Conversion | `char` (scalar), `double`, `disp` | Explicit MPFR conversion/formatting |
| Indexing | `A(i,j)`, `A(:,j)`, `A(i,:)`, `A(I,J)`, `A(k)`, `A(:)` | Read-only dense indexing; general vector-linear indexing remains limited |
| Assignment | Supported in-bounds scalar, row, column, submatrix and colon assignments | Immutable value-semantic deep copy |
| Unary arithmetic | `+A`, `-A` | Direct MPFR |
| Element-wise arithmetic | `A+B`, `A-B`, `A.*B`, `A./B` | Direct MPFR with supported singleton expansion |
| Matrix multiplication | `A*B` | MPLAPACK MPFR `Rgemm` |
| Left division | `A\B` | `Rgesv` for square; `Rgelss` for rectangular minimum-norm least squares |
| Structure | `A.'`, `A'`, `reshape` | Precision-preserving native copies |
| Concatenation | `[A,B]`, `[A;B]` | One contiguous dense `mp` value |
| Cholesky | `chol(A)`, `chol(A,"upper")`, `chol(A,"lower")`, optional status | MPLAPACK `Rpotrf`; selected-triangle semantics |
| QR | `qr(A)`, two-output full/economy forms, `"econ"`, numeric `0` alias | `Rgeqrf`/`Rorgqr`; one output is `R` |
| Pivoted QR | Three-output forms, `"matrix"`, `"vector"`, `"econ"`, numeric `0` vector form | `Rgeqp3`/`Rorgqr`; P/p are builtin structural doubles |
| LU | `lu(A)`, two/three-output forms, `[L,U,p]=lu(A,"vector")` | MPLAPACK `Rgetrf`, including rectangular and singular factors |

The factorization pages explain exact shapes, status behavior, and
reconstruction relations: [`cholesky.md`](cholesky.md), [`qr.md`](qr.md),
[`pivoted-qr.md`](pivoted-qr.md), and [`lu.md`](lu.md).

## Unsupported v0.1 surface

Complex values, sparse values, N-D arrays, matrix `char`, comparisons and
logical operators, matrix power, reductions, and general transcendental
functions are not implemented. Matrix growth, deletion assignment, logical
assignment, and the still-limited forms of vector-linear indexing are
intentional boundaries. `det`, `inv`, `rank`, `cond`, `norm`, `eig`, and
`svd` are not public APIs. `qr(A,B)`, QR update functions, LU updates,
automatic SPD solve optimization, sparse LU/QR/Cholesky forms, and complex
factorizations are deferred. Unsupported operations fail rather than
silently converting an `mp` value to binary64.

## Public-to-native map

The public wrappers in `inst/@mp` dispatch to the private native module
`__mplapack_core__.oct`. Major mappings are:

| Public method | Native command/backend |
|---|---|
| `mp`, `mpbits`, `mpdigits` | scalar/matrix constructors and precision commands |
| `+`, `-`, `.*`, `./`, unary signs | native MPFR scalar/matrix arithmetic |
| `*` | `mtimes` -> `Rgemm` |
| `\` | `mldivide` -> `Rgesv`/`Rgelss` |
| `chol` | `chol` -> `Rpotrf` |
| `qr` | `qr` -> `Rgeqrf`/`Rorgqr`; `qr_pivoted` -> `Rgeqp3`/`Rorgqr` |
| `lu` | `lu` -> `Rgetrf` |
| indexing/assignment/reshape/transpose/concat | corresponding private native structural commands |

Commands named `scalar_test_*`, `matrix_test_*`, and `module_test_locked`
are test-only and are not public APIs.

## Wrapper audit

Every file in `inst/@mp` is accounted for below.  The method wrappers are
supported public entry points unless marked as an intentional guard.

| Wrapper | Classification |
|---|---|
| `mp.m`, `mpbits.m`, `mpdigits.m` | supported construction/precision |
| `char.m`, `double.m`, `disp.m` | supported scalar conversion/display (`char` matrix is guarded) |
| `size.m`, `rows.m`, `columns.m`, `numel.m`, `ndims.m`, `isempty.m`, `end.m` | supported structural queries |
| `subsref.m` | supported dense indexing with documented limits |
| `subsasgn.m` | supported in-bounds value-semantic assignment with documented limits |
| `plus.m`, `minus.m`, `times.m`, `rdivide.m`, `uplus.m`, `uminus.m` | supported arithmetic |
| `mtimes.m`, `mldivide.m` | supported `Rgemm`/`Rgesv`/`Rgelss` paths |
| `mrdivide.m` | intentional stable unsupported guard |
| `transpose.m`, `ctranspose.m`, `reshape.m` | supported structure |
| `horzcat.m`, `vertcat.m` | supported dense concatenation |
| `chol.m`, `qr.m`, `lu.m` | supported real factorization APIs |

The native bridge also contains explicitly test-only commands (the
`*_test_*` family and `module_test_locked`) and diagnostics used by
`mplapack_version`; these are not accidentally public functions.

## Error namespace

New stable public guards use `mplapack:mp:<SpecificCondition>` (for example
`DimensionMismatch`, `NonSquareMatrix`, `InvalidOption`, `OutputCount`, and
`NotPositiveDefinite`). Legacy `mplapack:NotImplemented` remains for the
accepted right-division guard for compatibility with the existing test suite;
it is not a recommendation for new code. Native bridge errors are internal
diagnostics and are not part of the v0.1 programming interface.

| Identifier | Public condition | v0.1 status |
|---|---|---|
| `mplapack:mp:InvalidInput` | wrong constructor or method arguments | stable |
| `mplapack:mp:DimensionMismatch` | incompatible arithmetic/assignment dimensions | stable |
| `mplapack:mp:InvalidDimension` | invalid `size`/`reshape` dimension | stable |
| `mplapack:mp:IndexingUnsupported` | unsupported indexing or growth/deletion | stable |
| `mplapack:mp:AssignmentUnsupported` | unsupported assignment form | stable |
| `mplapack:mp:InvalidOption` | invalid factorization option | stable |
| `mplapack:mp:OutputCount` | unsupported number of outputs | stable |
| `mplapack:mp:NonSquareMatrix` | square-only operation receives rectangular input | stable |
| `mplapack:mp:NotPositiveDefinite` | one-output Cholesky failure | stable |
| `mplapack:mp:ComplexUnsupported` / `MatrixUnsupported` | outside real dense scope | stable |
| `mplapack:NotImplemented` | legacy `mrdivide` guard | compatibility exception |

Low-level `mplapack:InvalidNativeValue`, `NativeError`, and conversion
diagnostics remain internal bridge failures. `mpbits:*` and `mpdigits:*` are
the established precision-command validation namespace.

## Release scope

`0.1.0` is the frozen upstream version for the release candidate identified in
[`v0.1-release-manifest.md`](v0.1-release-manifest.md); M23 does not create the
final Git tag or publish a PPA. The package is built against the installed
MPLAPACK MPFR dependency discovered
with `pkg-config`, including the uniform-precision scope interface described in
[`precision-semantics.md`](precision-semantics.md). See
[`octave-compatibility.md`](octave-compatibility.md) for tested intentional
differences and [`ppa-plan.md`](ppa-plan.md) for the planned Ubuntu delivery.
