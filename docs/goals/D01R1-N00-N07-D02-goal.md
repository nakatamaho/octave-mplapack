# 3. Global numerical invariants

For every new operation:

```text
p_op = stored operand-derived arbitrary precision
```

Ambient `mpbits()` is not authoritative for existing values.

Mixed real/complex promotion follows the accepted C12 contract.

Never implement a numerical API through:

```text
double(mp) -> builtin double/complex operation -> mp(...)
```

Explicit `double()` conversion is the only binary64 conversion path.

Real input should remain on real MPLAPACK kernels when a real backend exists. Do not route all real problems through complex routines for convenience.

Destructive LAPACK calls use operation-owned copies. Public inputs remain immutable/value-semantic.

High-precision QA must use MPFR/MPC-native values and precision-scaled residuals, with mandatory 1024-bit/`2^-700` and 2048-bit/`2^-1500` coverage where applicable.

Reuse real/complex LU infrastructure (`Rgetrf` / `Cgetrf` or shared helpers). Compute determinant at source precision from permutation parity and the product of `diag(U)`.

Singular determinant must be exact zero according to Octave semantics.

Audit any optional second `det` output. If it is reciprocal-condition information and correct implementation naturally depends on N03, support one-output det in N01 and explicitly close the second output in N03.

# 7. N03 — `rank` / `cond` / `rcond`

Implement dense real+complex:

```octave
rank (A)
rank (A, tol)
cond (A)
cond (A, p)
rcond (A)
```

## rank

Use N02 singular values.

Default threshold follows Octave conceptually:

```text
tol = max(size(A)) * sigma_max * eps_at_stored_operation_precision
```

Never use binary64 `eps` for `mp` rank.

Rank is structural output, not arbitrary-precision payload, unless Octave differential QA dictates another representation.

Mandatory real and complex source-precision rank canaries: lower stored precision and higher stored precision must classify appropriately and ambient precision must not control the result.

## cond

Required forms:

```octave
cond (A)
cond (A, 2)
cond (A, 1)
cond (A, Inf)
cond (A, "fro")
```

Audit rectangular/singular semantics.

2-norm condition uses singular values when applicable.

For 1/Inf condition, audit stable estimators such as:

```text
Rgecon / Cgecon
```

on LU factors. Do not form an explicit inverse if a condition estimator exists.

Implement Frobenius condition consistently with Octave semantics and document method.

## rcond

Audit/use `Rgecon/Cgecon` or exact frozen equivalents for square dense matrices.

Return a real scalar.

If Octave `det` has a second reciprocal-condition output, close it here using the accepted condition machinery.

# 9. N05 — general `eig` + mandatory Grcar QA

Implement full dense algebraic eigenvalue problems for:

```text
real nonsymmetric
complex general
```

including balancing and left/right eigenvectors.

## Required public forms

Audit Octave 11.1 and support at minimum:

```octave
lambda = eig (A)
[V,D] = eig (A)
[V,d] = eig (A, "vector")
[V,D] = eig (A, "matrix")
[V,D,W] = eig (A)
... = eig (A, "balance")
... = eig (A, "nobalance")
```

`V` = right eigenvectors; `W` = left eigenvectors.

Match Octave's default preliminary balancing and exact option conflicts/errors.

## Backend audit

Audit:

```text
Rgeev / Rgeevx
Cgeev / Cgeevx
```

To implement explicit `balance`/`nobalance`, prefer the expert driver where frozen MPLAPACK evidence supports it. Do not fake `nobalance`.

Real nonsymmetric input may yield complex eigenpairs. Correctly convert the real LAPACK conjugate-pair representation into public complex `mp` values/eigenvectors. Prefer real backend for real input rather than routing all real problems through complex kernels.

## Equations

Right residual:

```text
A*V - V*D
```

Left residual:

```text
W'*A - D*W'
```

or equivalent columnwise normalized forms.

## Mandatory Grcar regression

Use:

```octave
A = gallery ("grcar", n);
Amp = mp (A);
```

At minimum:

```text
n = 8 or 16 for routine regression
n = 32 for deeper stress/release QA when runtime permits
```

Exercise:

```octave
eig (Amp)
eig (Amp, "balance")
eig (Amp, "nobalance")
[V,D] = eig (Amp)
```

Grcar is highly nonnormal. Do not use naive elementwise equality with binary64 eigenvalues as the main oracle.

Mandatory Grcar checks:

```text
A*V - V*D residual
default == explicit balance API behavior
nobalance path actually exercised
precision progression (e.g. 128/256/512/1024 where practical)
eigenvalue-set comparison uses matching, not raw ordering
sensitivity is documented
```

Do not call a high-precision answer incorrect merely because it differs visibly from binary64 for Grcar.

## Additional difficult fixtures

Add:

```text
near-Jordan block
nearly repeated eigenvalues
badly scaled nonsymmetric matrix
```

Use residuals and precision convergence.

Do not compare eigenvectors elementwise because sign/phase/scaling is nonunique.

Add a deterministic small 512/1024 and 1024/2048 eig precision canary separate from Grcar.

# 13. Eigenvalue test policy

General eigenvalues are unordered and eigenvectors are nonunique up to scaling/phase.

Never write fragile tests that compare general eigenvalues by raw position or eigenvectors elementwise.

Use a stable set-matching strategy for eigenvalues, such as minimum-cost matching by arbitrary-precision complex distance in test code.

Tolerance must derive from precision, scale, dimension, and conditioning.

For ill-conditioned Grcar/Jordan-like problems, residual correctness and precision trends are more important than equality to binary64 output.


Do not use binary64 numerical output as the sole high-precision correctness oracle.
