# /goal — D04 `mplapack-interop` 0.5.0 release freeze

## Mission

Freeze the T00–T14 development line as the reproducible
`mplapack-interop` 0.5.0 source release. D04 is release engineering and
release QA; it must not add numerical functionality or begin binary
distribution work.

The immutable predecessor is:

```text
package: mplapack-interop 0.4.0
tag: v0.4.0
commit: 34993eb569bfaa0d7665ae913a3a1f5a97ac2e31
archive SHA256: 6bc87d42fbda49fa72830db34fbede7b8b9f46b7614b14dc53e7619c7781536c
```

The accepted input is the `main` tree after T00–T14, SVT, NEIGT, and DOC00.
Historical milestone reports remain provenance records and are not rewritten
to make them appear to have used the later dependency release.

## Required order and gates

Run and record these gates in order:

1. `G-D04-PROVENANCE` — verify the official MPLAPACK archive, inspect its
   standalone release contents, and update current dependency handoff data.
2. `G-D04-DEPENDENCY-QA` — build or identify the installed MPLAPACK stack
   from the exact archive, prove include/pkg-config/runtime provenance, and
   rerun the applicable real, complex, precision, and sanitizer checks.
3. `G-D04-VERSION` — change the authoritative package version from
   `0.5.0-dev` to `0.5.0` only after the frozen dependency QA passes; update
   user-facing metadata, manual, generated manual Markdown, NEWS, README,
   Doxygen metadata, and release tooling consistently.
4. `G-D04-REGRESSION` — build the clean 0.5.0 source tree and run the full
   accepted T00–T14, SVT, NEIGT, real/complex, compatibility, documentation,
   package-lifecycle, and sanitizer walls that are available on the host.
5. `G-D04-REPRODUCIBLE` — build two independent source archives with the
   same controlled timestamp, compare SHA256, file list, top-level directory,
   and excluded private/build content, then replay from extraction.
6. `G-D04-FREEZE` — commit only release content, verify the exact freeze SHA,
   create `v0.5.0` only after all preceding gates pass, and verify the tag
   target. No GitHub Release, Debian package, PPA, Launchpad upload, or
   binary artifact is created by D04.
7. `G-D04-HANDOFF` — complete the D04 report/status and dependency manifest
   so the next binary-distribution milestone can consume the exact source
   commit, tag, archive, and checksum without repository archaeology.

Unexecuted tests are not PASS. A source-level defect found after a freeze
requires a new release-freeze/reopen record; it must not be silently edited
under an existing tag.

## Boundaries

Allowed changes are release metadata, release documentation, release tooling,
archive selection/reproducibility fixes, and a release-blocking fix that
reproduces an already accepted contract defect. No new public API, numerical
algorithm, fallback behavior, or dependency implementation is allowed.

Do not modify `octave-mplapack-ppa`, create Debian packages, upload to
Launchpad, submit an Octave Packages registry entry, or begin D01/B01–B05.
Preserve user-owned untracked files in the worktree.

## Final result

D04 may conclude only with:

```text
D04 PASS — MPLAPACK-INTEROP 0.5.0 SOURCE FROZEN
BINARY-DISTRIBUTION-READY
```

Then stop. The next milestone is a separate D01/B01 decision and is not
started automatically.
